# 北交大国旗仪仗队 · 推送文案

## 核心原则

**先问清，再动笔。缺信息就问，不许用想象填。**

这不是提醒，是硬约束。三个独立基线测试（无 skill 的通用 AI 写同样的题）无一例外在信息不足时**不停下来问，而是直接编**——编现场氛围、编队员感想、编队长讲话。它们没觉得自己在造假，因为把"氛围描写"划进了"文学加工"。

编出来的东西部长一眼看不出来，发出去就是事故。所以：

> **宁可交一篇带 `【待补】` 的半成品，也不交一篇读起来完整但掺了想象的成稿。**

## 流程

```
0 定类型 → 1 收信息（缺则问） → 2 出稿 → 3 三路并行审 → 4 改+问 → 5 复算 → 交
```

### 第 0 步 · 定类型

七选一（见 `references/03-类型骨架.md`）：升旗任务 / 训练总结 / 换届大会 / 入队仪式与授章 / 招新纳新 / 节日纪念日 / 通知公告。

类型决定**必备信息槽**，也决定**语域档位**：
- **通知公告、名单公示、会议纪要类** → 保守档：语域本就正式，只修标点与事实，不"去套路"
- **招新、人物故事、活动纪实类** → 可清理档：删空泛抒情、换成具体细节
- 判错档位会造成过度矫正，把正常的公文语体改坏

### 第 1 步 · 收信息（本 skill 最关键的一步）

按类型取必备信息槽（`references/03-类型骨架.md`），**逐项对照**。

**图片优先当作信息源。** 用户提供了活动照片时，先读图，从中提取可写的具体信息（场地、着装、队形、人数、天气、可见的横幅文字）。**照片里看得见的，可以写；看不见的，不许补。**

槽位为空时，**在动笔前一次性问清**，不要写完再问。问法：

```
动笔前我需要确认 4 项（直接回我序号即可）：
1. 执行中队与人数
2. 具体日期与时刻
3. 地点（如：思源楼广场 / 西操场）
4. 现场有没有授旗/宣誓/发言环节
```

**只有一种情况允许先出稿**：用户明确说"先给个框架我填"。此时所有未知处写 `【待补：具体内容】`，并在文末列出待补清单。

### 第 2 步 · 出稿

按 `references/03-类型骨架.md` 的骨架落笔。写作时对照：
- `references/02-用语对照表.md` —— 升旗/队列/国歌的准确用词（写错动词是老成员一眼能看出的硬伤）
- `references/04-反AI腔.md` —— 哪些句子形态一眼就是 AI 写的
- `references/05-本队语感.md` —— 本队真实推送长什么样（范文片段、句长、结尾习惯）

**标题必守格式**：`[类型标签] | [主标题]`，类型标签取自上表七类，主标题 ≤20 字且必须带核心事件信息。分隔符按 `references/01-规范要点.md`（该处手册与历史实践不一致，已标注）。

### 第 3 步 · 三路并行审

出稿后派三个独立子代理（`references/06-审稿代理.md` 有完整提示词模板），**必须并行、且彼此看不到对方的结论**：

| 代理 | 只盯一件事 |
|------|-----------|
| 合规审查 | 对照手册审核清单逐项过（结构、落款、用语、数字格式） |
| AI 腔审查 | 对照反 AI 腔表，标出每一处 AI 写法并给替换方向 |
| 事实核查 | **逐句问"这条信息从哪来"**——用户给的？照片里看得到的？还是编的？ |

事实核查代理是三个里最重要的。它只做一件事：把稿子里每一个具体信息（数字、人名、引语、动作、场景、天气、表情）标回来源；**指不出来源的，一律列为编造嫌疑**。

### 第 4 步 · 改 + 问

按审查结论修改。三类问题的处理不同：

- **合规问题** → 直接改
- **AI 腔** → 直接改（按 `references/04-反AI腔.md` 的替换方向）
- **编造或缺口** → **不许自己补**。能问用户就问；问不到的，删掉或改成不依赖该信息的写法，并列入待确认清单

### 第 5 步 · 复算

改了之后**重新跑一遍事实核查**（至少）。修改是最容易引入新编造的环节——为了"让句子更顺"，模型会顺手添一个不存在的细节。

**复算必须新派一个独立核查代理，不得由修改者自查。** 实测教训：修改者只删了编造的时刻、却保留了"下一个升旗日"这个编造事件，然后自查宣布"已收敛"——独立复核仍判 C 档。修改者对自己没改干净的条目没有判断力。

复算的输出必须是**当前文本**的完整来源表，不得引用上一轮结论打勾。迭代到独立复算 C 档 0 条为止。

### 交付

成稿 + **待确认清单**（所有 `【待补】` 与存疑项）+ 一句"人工通读提示"。

## 红线（违反任何一条，稿子不能交）

1. **不编引语。** 队长讲话、老师讲话、队员感想，必须来自用户或本人确认。**禁止用"有人说""队员们表示""大家纷纷表示"引入不存在的发言**——这是基线测试里最高频的编造手法。
2. **不编场景细节。** 天气、表情、汗水、掌声、眼眶、孩子、家长——用户没给、照片里没有，就不写。
3. **不编数字。** 人数、时长、届次、步幅、奖项。
4. **该类型必备信息缺失时，不交稿**，先问。

## 常见借口与实情

| 借口 | 实情 |
|------|------|
| "氛围描写属于文学加工，不算编事实" | 用户没提"孩子被家长抱在怀里"，写了就是凭空造了一个现场。编辑一眼看不出，读者以为真发生过。 |
| "用'有人说'概括队员心声是常规写法" | 概括的是**不存在**的心声。要么用真实原话，要么写成"队员们表示"以外的、不指认具体人的中性叙述，要么删。 |
| "队长的话可以概括提炼" | 提炼后的句子挂在队长名下，就是杜撰引语。要么有原话，要么写"队长就训练安排作了部署"这类不引述的叙述。 |
| "留了 `【待补】` 就是留了余地" | 占位符只覆盖你**自觉是事实**的部分。氛围细节照样会被编进去，而它没有占位符。 |
| "这篇时间紧，先发出去再改" | 基线测试里 AI 就是这么说服用户直接发的。缺信息时先问，比返工快。 |
| "加点抒情更打动人" | 手册红线：结尾抒情不超过正文 1/5。抒情超限是部长驳回的第一大原因。 |

## 红旗清单（出现即停手复查）

- 你正在写一个用户没提过的具体场景（天气、表情、声音、人数）
- 你正在写引号里的话，而那句话不是用户给的
- 你用了"有人说""有人说""大家纷纷表示"
- 你的结尾在讲"精神""传承""新时代"，而正文没提具体的人或事
- 你写完了但一个 `【待补】` 都没有——信息从来不会这么全
- 稿子读起来很顺很美，但没有一句是只有这支队伍才写得出的
